# 可解释的 GPU 服务模型

创业赛使用 `lib/compute-model.js`（普通工坊现使用独立的 `lib/workshop-sim.js` 资源仿真），以运算量、访存流量、有限发射能力和延迟隐藏推导服务时间。它替代原先将多个部件升级倍率直接相乘的处理速度规则；经营价格、客户需求与融资规则仍属于独立经济模型。

## 一颗 ALU 如何工作

开局配置是一颗浮点 ALU、一个基础时钟，没有安装缓存或板载显存。输入通过教学模型的外部供数链路到达，不能理解为真实 ALU 脱离寄存器、控制与输入系统独立运行。

代表性 FP32 服务块包含 256 次逻辑操作与 1,024 字节输入。基础配置的计算时间、数据搬运时间和访存延迟分别计算，得到完整服务时间。每种负载均以自身裸 ALU 配置归一化为 1 单位服务吞吐；不能跨负载把这个数字当作真实 FLOPS。

## 处理速度的来源

| 组成 | 规则 |
| --- | --- |
| 计算 | 串行启动成本与向上取整的指令发射批数；ALU 和时钟提供有限发射能力 |
| 矩阵 | 仅负载的矩阵部分进入 Tensor 执行能力，普通浮点不会自动获得矩阵加速 |
| 缓存 | 工作集、复用机会与 L1/L2 容量推导条件命中；缓存无法消除必需输入 |
| 搬运 | 命中和未命中的流量分别除以对应层级带宽，再累加服务成本 |
| 延迟 | 依赖加载延迟由有限独立请求与调度能力隐藏，不能无限隐藏 |
| TMA | 提高适合异步负载的计算与搬运重叠，重叠最多覆盖两者中的较小部分 |
| TMEM | 留存一部分矩阵累加器数据，减少溢出搬运，不减少必需输入 |

总模型周期 = 计算周期 + 搬运周期 − 可重叠周期 + 延迟成本。

吞吐 = 当前负载裸 ALU 基准周期 / 当前配置模型周期。

因而增加 ALU 不保证线性加速：当外部供数主导时，继续堆 ALU 的边际收益很小。增加缓存也不会让主要读取新数据的流式负载获得与高复用矩阵相同的收益。

创业赛的「性能模型」窗口可检查输入、周期分解、缓存命中、重叠比例与主导瓶颈。商店展示当前实际负载在升级前后的模型差值，同时显示运营成本变化。

GPT-3 项目使用 70% GEMM 与 30% 注意力的服务时间混合，取调和吞吐；训练按前向与两条反向路径共三个代表性 pass 计算，商业首单为一个推理 pass。项目分配公司 70% 算力，余下 30% 服务普通订单，因此训练速度不会由普通订单种类的平均吞吐替代。

## 参数和可信范围

全部工作集、带宽、逻辑延迟与阵列能力均在源码中明确给出，属于未校准的教学假设。此实现是解析数学模型，没有声称运行真实 CUDA、逐周期复现某款 GPU、完成实机标定，或训练了 XGBoost。

若后续获得可靠硬件测量，可以用相同的输入特征和周期分解生成校准样本，再拟合 XGBoost 或其他代理模型。不能把模型自生成的样本描述为真实测量。
