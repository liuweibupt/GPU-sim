# Three independent natural Triton GPU failures

This expansion uses three merged upstream fixes absent from official Triton 3.8.0:
softmax axis preservation (PR 11409), signed floating zero (11426), and constexpr
comprehension predicates (10888). They are frontend/library defects whose numerical
consequences execute on a physical RTX 4090. They are not asynchronous-memory faults.
No candidate was selected based on any model's success or failure.

`prepare.py` applies exact upstream Python patch hunks, with fuzz disabled, in a
separate official-wheel tree. It keeps original library source, native compiler
hashes, upstream patch/parent/merge identifiers and license. `archive_upstream.py`
retains exact upstream files and verifies the five original affected files against
the official release tag. The comparison is release plus selective backport; it is
not an exact-parent native compiler rebuild.

`run.py` executes 11 cases per root cause (3 visible and 8 withheld), saving complete
output bytes, independent reference inputs, compiler IR/PTX and cubin hashes. The
signed-zero wrapper contains separate literal -0.0 and +0.0 paths. Its initial
float-constexpr parameter form additionally exposed an in-process cache-key
collision; that first run and its original harness are retained separately and
excluded from the final controls. This adjustment is shared by before and gold.

`verify.py` independently recomputes the numerical/bitwise oracle from the frozen
plan, verifies full output lengths and source/artifact hashes, and rejects missing
cases. Its oracle does not trust the runner's reference values or pass flag. Six
adversarial tests cover false pass reports, complete family omission, truncation,
signed zero and independent softmax/filter references.

`make_catalog.py` creates the before-only `repair-study-catalog-v2` task pack and a
separate private scoring plan. Each task contains ten actual complete implementation
files (all editable), one immutable visible kernel, and three complete observations.
The hidden cases and gold locations are never supplied to candidate generation.
Holdout refers to this tool's development, not model pretraining.

`evaluate_candidate.py --candidate FILE --output NEW_DIRECTORY` accepts the exact
`core.applyEdits` candidate object. It validates every before/after file and tree
hash, creates an isolated runtime overlay without mutating the base, executes all
11 cases under a bounded subprocess and minimal environment, then returns a
`runtime-record.json` and independent verifier receipt. Hidden endpoint records
contain the eight withheld cases; visible controls are separately retained. The
run summary's `variant=before` denotes its base wheel lineage; candidate source
identity is determined by all applied file hashes, never that display label.
There is no manual repair, hidden-test feedback or model retry inside this helper.

`publish.py --output NEW_DIRECTORY` curates source, raw outputs and text compiler
artifacts, excluding native runtime trees, ELF/cubin, caches and wheels. Binary
identities remain in hash receipts. No performance inference is made from these
shared local GPU correctness runs.

The evaluator computes candidate tree identities with the same Node
`localeCompare` and `JSON.stringify` algorithm as `core.applyEdits`; Python's path
sorting is not interchangeable. Three gold controls generated by the actual
`core.applyEdits` function were re-executed separately and all passed 11/11 cases.
Their artifacts are `core-control-candidates` and `isolated-gold-core-*`.
Two identity tests supplement the six oracle tests, for eight checks in total.

Evidence stages must remain separate:

| Artifact | Interpretation |
|---|---|
| `run-before`, `run-gold`, `run-v1.py` | Initial screening; signed-zero cases also include the constexpr cache collision. Excluded from final controls. |
| `run-before-v2`, `run-gold-v2` | Final shared harness; original wheel vs combined upstream patches, 33 cases each. |
| `isolated-gold-*` excluding `core` | One upstream root-cause patch at a time; 11 cases per root. |
| `isolated-gold-core-*` | Actual `core.applyEdits` output through the final evaluator; 11 cases per root. |
| `candidate-evaluations/*` | Unmodified model candidate execution, after all generation ends. |

Known upstream gold controls are not counted as agent-generated repairs, and
repeated control executions are not additional independent defects.

The curated package supports **offline numerical verification using Python only**:

```sh
python PACKAGE/reproduction/publish.py --verify-package PACKAGE --receipt /tmp/offline-receipt.json
```

This checks every published file and rejects missing/extra files, native binaries,
source-identity mismatches and changed output bytes. It runs the archived verifier
against the complete saved device outputs, with a category for each evidence stage.
It does not need a GPU, PyTorch, Triton, network or a native compiler installation.
Keep the verification receipt outside `PACKAGE`, because the package is immutable.
Fresh GPU reproduction still requires reinstalling the identified wheel and CUDA
PyTorch environment; an offline oracle recomputation is not another GPU execution.

A representation audit discovered after generation started is retained in
`signed-zero-representation-audit.json`: JavaScript `JSON.stringify` canonicalizes
numeric `-0` to `0` in the model packet. Complete reference/device byte patterns
remain identical to the original observations, so they still encode the sign bit
and exact contract; the Python execution plan is unaffected. Both conditions get
the same packet. Grouping by the numeric `value` alone cannot distinguish the two
zeros. The frozen trial is left unchanged, with no corrective model prompt or
candidate retry; an explicit sign-bit field belongs in a future protocol revision.

Passing a hidden suite means passing this frozen contract, not proving a complete
library repair. The softmax suite uses contiguous finite float32 blocks and the
kernel's default `keep_dims` call; it does not cover arbitrary user call sites,
explicit legacy `keep_dims` arguments, autograd, or all ranks/dtypes. Signed-zero
coverage is limited to the four declared floating types (no FP8 contract).
Comprehension inputs and predicates are constexpr integers; runtime predicates,
other target forms and arbitrary nesting are outside the suite. Candidate patches
are not retuned against these untested dimensions after generation.

The completed v2 study executed 18 Triton model candidates (3 root causes × 2
conditions × 3 model draws). Each condition passed 3/3 repairs for each root; all
18 candidates passed all 11 cases, totaling 198 completed device cases (144 hidden,
54 visible) and 9,390 independently checked output elements. This subset therefore
demonstrates no repair-success advantage for the extra diagnostic operations.

One long-lived physical-validation orchestrator exited externally with status 143,
after 11 complete candidates and during preparation of the next candidate. Its
incomplete directory, original log, candidate bytes and a 469-file hash/size
inventory are retained under `interrupted-attempts`. There was no complete output
array or runtime receipt for that attempt, so whether any device operation started
is unknown. The same frozen candidate was validated again in a fresh directory;
no model was resampled and no source, test or native compiler was changed. The
18 complete runs use those final verified arrays; the incomplete attempt is counted
separately and is not silently discarded or labeled a numerical failure.
