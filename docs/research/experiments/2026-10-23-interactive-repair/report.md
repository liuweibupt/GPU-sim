# 真实故障交互诊断与 agent 定位／修复对照

日期：2026-10-23。接续[真实故障、隐藏测试与成本](../2026-10-23-real-evidence/report.md)。本轮完成交互诊断入口，以及有／无专用诊断查询的实际 agent 修复对照。**两组均修复全部六次尝试，尚未证明诊断工具提高成功率或速度。**这是两个已给定单文件范围、原始证据完整的公开缺陷；不能外推为人类理解收益或实际仓库盲诊断能力。

## 1. 系统接入与可核验证据

[打开交互诊断页](../../../../web/research/natural-bugs/index.html)。运行 `npm start` 后，也可从 GPU 计算城市顶部“真实故障诊断”进入 `/web/research/natural-bugs/`；页面自包含，可离线打开。

系统汇入此前的 **108 次真实运行**（CUTLASS 76、Triton TMEM 32），提供病例／版本／结果筛选、同参数修复前后切换、静态 TMEM 列区间、源码搜索与行定位、实际输出分页、原始证据与 SHA 导出。版本之间的重复执行保留独立 ID，不合并成独立根因。浏览器测试遍历全部病例，核对 140 次源码定位、92 次分配区间点击、17,824 个可见输出单元和 108 份导出结构，并检查筛选、空结果和实际下载 handler。

TMEM 页面保留完整观测输出并分页；CUTLASS 页面明确标为每组前 16 个解码元素的样本，完整输出仍通过归档字节核验，不把页面样本当作全部数值证据。

TMEM 横轴表示静态列号。区间重叠由实际编译 MLIR 的 allocation/store/select/load 重新计算，没有画成硬件时间轴。CUTLASS 超时也没有对应的动态 wait 位置；界面保留这一未知边界。β=1 的正 K 失败与本次 β=0 空 K 修复目标分开显示。

浏览器与评测使用同一个 `queryDiagnostic(data, request)` 后端，提供 `cases/case/evidence/source/overlap/contrast`。完整浏览器数据有修复前后版本；评测使用**单独的 before-only 文件**，没有修复版、补丁、issue URL、提交号或事后解释。源码本身是可识别的公开代码，隐藏标识不能证明模型没有训练记忆。

## 2. 冻结协议与公平性

冻结时间 **2026-10-23T13:41:59.615Z**，之后才开始候选调用。对象为 CUTLASS 空 K 和 Triton selected TMEM descriptor 两个根因，每条件各三次独立尝试，共 **12 个候选、30 次模型调用、18 次实际查询**。模型沿用 `gpt-6-astra` / low，记录实际 CLI 版本与 argv，不把别名写成不可见的权重快照。

| 项目 | 原始证据条件 `raw` | 诊断条件 `diagnostic` |
|---|---|---|
| 输入 | 相同旧版完整可编辑文件、病例、观测与编译 IR | 完全相同 |
| 普通能力 | 读取病例、原始证据、源码范围／文字搜索 | 相同 |
| 额外能力 | 无专用诊断查询 | `contrast` 分组；`overlap` 解析静态 TMEM 关系 |
| 预算 | 最多两次查询、三次模型调用；每调用 90 秒 | 相同 |
| 首轮 | 必须作一次普通查询 | 必须作一次专用诊断查询 |
| 修改范围 | 只改一个指定旧版源码文件 | 相同 |
| 反馈 | 不提供编译／测试结果，零修复反馈轮次 | 相同 |

“无工具”在这里准确指**无专用诊断工具**，仍允许普通源码／证据读取。两组输入 packet 逐字一致，长数值序列用可逆 RLE 编码完整保留。最多两路并发，按根因配对并交错条件顺序。实际 token 消耗记录而不强行相等；所比较的是查询后端的有界辅助能力，**不是视觉界面布局效果**。

每次 CLI 调用使用空临时目录、ephemeral 会话、忽略用户配置、禁 shell，并检查 JSONL 无外部工具调用。轮间只重放本 trial 的可见请求／响应；候选之间没有共享历史。没有声称这是正式保密沙箱。所有候选先生成完毕，才统一编译和运行；没有手改候选、挑选通过样本或基于隐藏结果重新提示。

输入已经定位到一个文件：CUTLASS collective header 或 Triton `TensorMemoryAllocation.cpp`。这显著缩小了任务，不能将结果称作跨文件自动根因搜索。

## 3. 实际构建、隐藏回归与控制

每个回答给出 `{old,new}` 精确文本替换，逐项必须唯一匹配；结果源码 SHA 与候选构建绑定。CUTLASS 在私有旧版树中编译。Triton 单独编译 allocator 对象并重链，其他对象与依赖只读复用；新 wheel 只改变 native compiler 和 RECORD，逐成员检查其余内容一致。没有覆盖上轮已审计源码。

12 个候选共有 **11 个不同完整源码**：`tmem.raw.r1` 与 `tmem.diagnostic.r2` 逐字相同，编译与 GPU 结果按 SHA 严格复用。它们仍是两个模型尝试，但不是两次物理 GPU 执行。11 个唯一候选都实际编译成功；五个唯一 Triton compiler 另通过原样 CPU allocation lit。lit 的布局要求独立报告，不将复刻官方布局当作一般数值修复的定义。

| 回归合同 | 每个唯一候选的实际检查 | 原始失败版控制 | 官方修复控制 |
|---|---|---|---|
| H100 CUTLASS | 4 个已知 normal + 12 个隐藏 normal + 2 次隐藏 memcheck | 4/18 通过；其余超时 | 18/18 通过 |
| B200 TMEM | 16 个已知配置 + 32 个隐藏常数组合 | 27/48 通过，86,016 错误元素 | 48/48 通过，零错误 |

CUTLASS 隐藏输入包含不同组数、零 K 位置／数量、128/256 M/N 与两种 host-shape 模式，β 固定为 0。因为旧版 β=1 连非零 K 对照也失败，不把另一故障混入本次补丁评分。完整 FP8 输出、组 ID／shape、stdout、退出码、超时与 memcheck 完整摘要重新核验；K=0 使用独立零值 oracle，K>0 reference 仍是上游 CPU 实现。

TMEM 隐藏用例将原来的 3/5/7 改为 11/13/17 和 −2/9/23，保留相同 16 种合法选择／temporary 配置。这是输入泛化检查，不是新增根因。每个元素按独立常数 oracle 重算，TEMP_COLS=0 排除未使用 temporary；安装后 native compiler SHA 绑定候选。缺失、异常中止或未完成的 case 不从分母删除。

## 4. 定位与实际修复结果

| 根因 / 条件 | 目标函数位置命中 | 实际编译成功 | 完整 GPU 回归通过 | 模型调用墙钟中位数（范围） |
|---|---:|---:|---:|---:|
| CUTLASS / raw | 3/3 | 3/3 | 3/3 | 55.24 s（52.72–56.61） |
| CUTLASS / diagnostic | 3/3 | 3/3 | 3/3 | 69.07 s（53.38–73.02） |
| TMEM / raw | 3/3 | 3/3 | 3/3 | 41.41 s（38.45–43.58） |
| TMEM / diagnostic | 3/3 | 3/3 | 3/3 | 40.91 s（38.03–45.00） |

每个 CUTLASS 候选通过 18 项检查，完整验证 **2,326,528 个输出**；每个唯一 TMEM 候选通过 48 项检查，验证 **516,096 个输出**。候选阶段物理执行共 **348 个 case、16,539,648 个完整输出、12 次 memcheck**；控制组另计。此处没有把共享编译／运行结果重复计成物理执行。

工具组在两根因上的成功率增量均为 **0 个百分点**。CUTLASS 工具组调用墙钟更长，TMEM 两组接近。这些时间含服务、排队、网络和模型调用，不是独立思考时间或人类任务完成时间。只有两个根因、每格三次模型抽样，**不作总体显著性、等效性或普遍速度结论**。

定位只测“有限行区间是否命中预定义相关函数”，并不自动证明解释完全正确。另独立检查实际观测引用，保留了下面的评分实现限制。

### 冻结评分的限制与透明补充

冻结 `supportedLocalization` 有两个问题：只接受可编辑文件 ID，因而把有效 MLIR 源位置也记为 invalid；共享的静态 IR fact 又可能同时取得失败和通过引用信用，弱于“引用实际失败及通过观测”的要求。独立审查使用合成评分输入复现了后一个问题。

未修改冻结代码、原始回答或分数。原严格复合分数为 CUTLASS 两组各 3/3、TMEM 两组各 0/3；**位置命中子指标仍是两组各 6/6**。明确标记为事后补充的审计允许引用所有已提供源文件，并要求实际 case／device-output／execution-observation 分别覆盖失败和通过，12 个候选均满足。这个事后分数不替换原分数，不用于声称工具优势；GPU 修复主终点完全独立。

## 5. 成本及能支持的结论

| 根因 / 条件 | 实际查询次数（3 trials 合计） | 输入 token 合计 | 输出 token 合计 |
|---|---:|---:|---:|
| CUTLASS / raw | 6 | 446,774 | 2,636 |
| CUTLASS / diagnostic | 6 | 369,083 | 3,247 |
| TMEM / raw | 3 | 279,615 | 2,538 |
| TMEM / diagnostic | 3 | 281,512 | 2,291 |

缓存与 reasoning token 的原始字段另存，不能将上表不同口径相加当计费额。完整源码和可见历史会在轮间重放，输入成本并不低。编译、wheel 打包、GPU 命令墙钟与查询处理耗时分别记录；没有用远程总墙钟推算 GPU kernel 性能或准确云账单。

**已经支持：**两个真实故障可在交互页中回查，agent 可调用同一来源绑定的诊断后端，并将原样候选闭环到实际 H100/B200 回归。

**尚未支持：**专用工具提高成功率、缩短端到端修复、人类理解／信任提升、跨独立根因泛化、生产开销可接受。当前完整证据和单文件范围已经使基线达到天花板；不能通过削弱基线、挑失败随机种子或改评分制造优势。

下一轮应另行预注册：跨多个文件且含干扰线索的未用过真实故障；让两组按相同信息获取预算自行发现相关证据；以首次可执行修复、必要证据获取成本与错误建议拒绝率为主要终点。若要主张界面帮助人理解，增加对应的人类任务，而不把本轮文本 agent 结果改名为用户研究。
