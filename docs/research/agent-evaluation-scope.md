# 实机与 agent 评价：不以模拟参与者替代人类结论

更新：2026-10-23。稿件状态：研究规划与已执行实验，尚非完成稿。目标优先为 VIS/TVCG 的可视分析系统；TOG/SIGGRAPH 取决于图形与交互贡献；若主贡献转向 GPU 分析算法和工具，可评估体系结构/系统方向。AI 算子是应用范围，不自动决定投稿社区。实际数据见[现代 GPU 与 agent 实验报告](experiments/2026-10-23-modern-gpu/report.md)。

## 1. 开发者测试是否必须真人

**技术论文不一律要求用户研究，但关于人的结论需要来自人的证据。** [VIS 2026 审稿说明](https://ieeevis.org/year/2026/info/call-participation/review-instructions/)允许依贡献类型采用不同有效性评价；[SIGGRAPH 2026 审稿说明](https://s2026.siggraph.org/technical-papers-reviewer-instructions-ethics/)明确说明，不是每项贡献都需要端到端应用或用户研究。前者对应 VIS full papers 的 TVCG 发表路径，后者涵盖 SIGGRAPH 的 TOG journal track；不把这些年度规则泛化为所有常规期刊投稿的保证。

| 待支持主张 | 可以直接支持它的证据 | agent 能否替代真人 |
| --- | --- | --- |
| 输出正确、版本错误可检出、修复恢复结果 | 实际 GPU 执行、独立数值 oracle、支持范围内的 sanitizer、源码与指令绑定 | 不需要真人作为数值真值；agent 可提出候选，程序独立检验 |
| 三值协议义务与证据切片有效 | 独立有限模型、反例、证据缺失/扰动消融、见证保留检验 | 不需要真人；不能用同一 LLM 的自评作为唯一真值 |
| 表示帮助 agent 完成诊断 | 固定模型/预算、相同信息、独立会话、盲测任务、程序评分 | 可以直接做 agent 实验；结论限定为该模型与任务分布 |
| 实际工作流可用 | 可复现的真实故障/修复案例、成本与边界、适当的领域专家走查 | agent 可验证工具可调用；专家意见仍要由真实专家提供 |
| 人理解更快、信心更校准、能迁移到新任务 | 人类预测/核验任务、错误建议接受率、独立迁移测试；适用时可复用匹配的既有人类数据 | 不能将 agent 分数作为这些人的结果 |
| 可视编码比原始表示更好 | 针对该编码的感知/交互任务与相称评价 | 文本/JSON agent 实验不证明颜色、布局或交互对人的收益 |

因此当前可先完成**“GPU 版本与完成义务的证据系统，以及 agent 可消费的核验接口”**，把“使人能独立理解”保留为动机与后续假设。不是把真人研究改名为 synthetic user study。若继续把人类理解作为论文核心贡献，就补直接的人类评价；研究规模应由主要终点和任务方差决定，不机械要求某个固定人数。

LLM 模拟研究本身也需要验证。[Aher 等，ICML 2023](https://proceedings.mlr.press/v202/aher23a.html)在若干经典实验中复现了人类结果，同时观察到系统性失真；它没有验证 GPU 开发者的学习、信任或调试行为。让多个 agent 扮演不同资历的人，不会自然获得独立的人类样本。

## 2. 本轮 agent 先导的实验单位

本轮只验证**有限协议证据的读解与出处引用**。任务来自已有手工开发 corpus，经独立有限全序枚举获得目标答案；它是 development pilot，不是自然 AI 故障或冻结的新根因测试集。待测 agent 不看到答案、解释标签、原用例名称或仓库文件。

- 冻结 12 个任务，satisfied / violated / unknown 各 4 个；每个任务有两个等信息表达：平铺字段文本和结构化 JSON。完整 generation 以十进制字符串保存。
- 两个条件均只提供事实、规则和待查义务，不额外给某一条件检查器 verdict、推导路径或建议答案。预先记录输入哈希，并检查两种表示的信息对应。
- 固定本地已配置的 `gpt-6-astra`、low reasoning；每任务每条件两次独立调用，共 48 次。记录 CLI 版本、全部可见参数和调用时间；模型名不能冒充服务端不可见的模型权重快照。
- 使用临时空目录、ephemeral 会话、忽略用户配置、禁用 shell；保留原始 JSONL 并检查工具调用。额外工具调用、解析失败、超时作为失败/污染报告，不静默重试或删除。
- 独立程序评分状态、unknown 拒答、引用是否在给定证据内，以及引用的有限充分性。自然语言解释若无完整语义评分，只保留供核查，不把合法 JSON 当正确解释。
- 重复调用不是独立开发者。统计按任务配对，报告每题与每状态结果；12 题不足以声称跨模型或真实任务分布的显著泛化收益。若两个条件都满分，应报告天花板效应，不创造提升。

这个先导不涉及 agent 修改 CUDA，也不测量视觉交互。下一轮修复任务必须另行冻结代码、工具预算与隐藏输入，使用实际编译及隐藏正确性检查评价修复；诊断正确不能自动计为修复成功。

## 3. 无真人阶段的论文证据组织

| 论文部分 | 应呈现内容 | 当前到下一阶段的验证要求 |
| --- | --- | --- |
| Introduction | 异步 GPU/AI 算子中，相同存储与重复 phase 无法唯一说明消费了哪个逻辑版本；代码可生成而主张难核验 | 用实际旧版本结果和等待成功观测说明问题，避免以 AI 生成速度替代调试困难的证据 |
| Related work / tasks | 与执行/依赖可视化、性能追因、同步检测器、LLM 调试工具分别比较 | 固定公开实现版本与支持范围；没有运行的基线只作功能/文献讨论 |
| Model / method | 逻辑任务身份、完整 generation、分类型 completion domain、源证据绑定、三值义务、见证保留切片 | 定义假设与证明边界；独立模型与反例；不把源码合同当任意 SASS 的自动分析 |
| System | 采集→证据→义务→跨运行差异→人/agent 查询 | 记录 source/PTX/SASS/输入/输出与原始事件位置；前端不能把 unknown 显示为“没有 bug” |
| Evaluation RQ1 | 实际数据和完成结果是否被保真表达 | 两架构 TMA、SM100 tcgen05/TMEM；数值 oracle、实际成功 wait、完整版本、支持范围内 sanitizer |
| Evaluation RQ2 | 检查器在证据完整/缺失时能否作正确结论 | 完整与删版本/删 HB 消融、TP/FP/FN/unknown、有限 oracle 对照、切片证据完整性 |
| Evaluation RQ3 | agent 是否能消费该证据 | 等信息条件、独立盲测、程序评分、每任务结果；扩大为根因分组保留集后再下泛化结论 |
| Evaluation RQ4 | 是否支持实际有用的调试/优化决策 | 真实 bug 与修复；隐藏形状/输入；未插桩端到端时间、采集/分析成本分别计量 |
| Discussion / conclusion | 哪些主张由实际观测支持，哪些仍未知 | 人类理解收益、自然 AI 故障泛化、生产规模性能不能由受控单 CTA 实验代替 |

### 仍需补的外部材料

1. **真实故障/修复和 AI 候选记录**：确切 commit、最小复现、输入、症状、候选生成历史与运行预算。这比继续扩大同一个人为故障的 seed 数更能补外部有效性。
2. **生产采集器身份和支持范围**：tracer commit、加载二进制 SHA、记录时点/丢失声明。当前自写探针的完整合同不能追认旧 trace 的未知字段。
3. **真人仅在相应主张需要时**：独立理解与迁移的直接观察；少量专家走查可帮助修正任务和接口，但不能被写成总体效应估计。

Modal 的 B200/H100 已成为本轮实际使用的资源，现代 GPU 访问不再是原先的硬阻塞。有限微实验通过也不代表可立即提交 TOG；接下来决定论文强度的是独立根因、真实工作流、基线公平性和可视分析贡献。
