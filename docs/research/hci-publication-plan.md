# GPU-sim 的 HCI 投稿与实验方案

日期：2026-10-19。正式研究尚未开展；当前增加独立的三场景探索原型与本地事件导出。本文区分工程原型、形成性试运行和待冻结的正式研究，不包含参与者结果。

配套文件：[三场景试运行手册](gpu-exploration-pilot.md)、[学术近邻](hci-related-work.md)、[机器可读指标协议](hci-metrics-protocol.json)、[测验题与评分草案](hci-assessment-draft.md)。现有玩法见[叙事设计](../narrative-design.md)，模型边界见[计算模型](../compute-model.md)。

## 1. 投稿判断

**优先准备 CHI，IEEE VIS 是另一条适合现有技术基础的研究方向；CSCW 应作为真实协作版本的独立研究。** 当前原型已有可复现规则、可修改模型、叙事选择和多种尾声，但缺少独立测验、完整研究日志和人类参与者证据。增加剧情、组件或结局数量本身不足以建立论文贡献。

CCF 2026 年目录将 CHI、CSCW、UIST、UbiComp 列为人机交互与普适计算 A 类会议，IEEE VIS 列为图形学与多媒体 A 类会议；TOCHI 为 A 类期刊。目录依据为 CCF 编写的[原始 PDF（研究组镜像）](https://scdm-shu.github.io/ccf/2026-CCF-Ranking.pdf)，其中第 64、47、61 页分别可核对相关条目；版本发布信息见[CCF 官方页面](https://www.ccf.org.cn/Academic_Evaluation/By_category/)。镜像用于读取原表，不把镜像维护者的解释当作认定规则。

| 目标 | 对本项目成立的研究问题 | 必须补齐的贡献与证据 | 建议 |
| --- | --- | --- | --- |
| CHI，A 类会议 | 学习者如何把系统资源、干预和后果联系起来，能否迁移到新任务？ | 新交互机制、形成性研究、强对照、独立迁移测验和解释分析 | 主线 |
| IEEE VIS，A 类会议 | 多尺度证据与受控比较能否改善 GPU 瓶颈诊断？ | 超越既有 GPU 可视化的任务/表征贡献、专家真实诊断案例、证据定位与诊断评价 | 若重点转向分析工具，则独立组织论文 |
| UIST，A 类会议 | 是否产生可泛化的仿真操纵、反事实比较或交互作者工具？ | 明确技术新颖性、机制实现与系统评价 | 当前功能组合还不足，暂不优先 |
| CSCW，A 类会议 | 不同角色如何借助共享仿真交换证据、协调资源与交付责任？ | 真实人际协作、任务相互依赖、协商过程和团队结果 | 后续独立版本 |
| TOCHI，A 类期刊 | 上述 HCI 机制在多轮研究和较长部署中如何发挥作用？ | 更完整、深入的研究链与可推广解释 | 期刊备选；与会议选择遵从各自投稿政策 |

上述匹配是研究设计判断，不是录用概率。CHI 要求原创 HCI 贡献和与主张相称的验证，并不规定所有论文采用同一种用户实验。[CHI 贡献指南](https://chi2027.acm.org/contributions-to-chi/)

**CSCW 的两个边界尤其重要。** 当前一位玩家与 NPC 互动没有构成真实协作研究；官方 CFP 明确将主要服务单个用户、包括一人与多个 AI agents 的协作研究排除在范围之外。2027 年及以后，官网说明通过 PACM HCI/CSCW 或符合 CSCW 范围的 TOCHI 已录用论文申请会议报告，没有面向某届会议的统一论文截止日。[CSCW 范围](https://cscw.acm.org/2026/papers.html)、[2027 及以后投稿路径](https://cscw.acm.org/2026/rolling.html)

CCF 原表另将 PACMHCI 列为 C 类期刊、Springer 的 Computer Supported Cooperative Work 列为 B 类期刊，二者与 CSCW A 类会议不是同一个条目。因此成果认定需要核对具体专题、论文身份及本单位口径，不能把所有 PACMHCI 论文统称 CCF A。Demo、Workshop、Short 等也不直接等同于目录中的正式 Full/Regular 论文。

时间上，CHI 2027 Papers 截止日是 **2026-09-10**，截至本方案日期已经过去；从现在开始的研究按下一次正式 CFP 或合适期刊安排，不编造尚未核定的 CHI 2028 日期。[CHI 2027 官方日期](https://chi2027.acm.org/Authors/Papers/)

## 2. 把原型收敛成一个可研究的问题

建议题目方向：

> **让 GPU 机制成为可操作对象：对象化交互能否帮助学习者理解系统瓶颈？**
>
> Manipulating GPU Resources: Object-Based Representations for Understanding System Bottlenecks

目标人群先限定为具备基本编程和计算机组成知识、尚无专业 GPU 优化经验的 CS/AI 学习者。硬件专家参与目标与题库审查，不把专家和新手混为一个无分层样本。

**核心问题：模型、任务、可执行动作、原始事实、比较和解释工具以及学习时间相同时，以可操作的 GPU 对象和数据流呈现机制，相较抽象交互表示，是否改善未见情境的诊断与预测？** 趣味性是重要次要结果。这是屏幕上的图形对象表示研究，不是 VR、实体硬件或身体具身交互研究，也不能据此证明整个经营游戏的教学效果。

第一轮只改变表示方式。此前的“可检查反事实证据”保留为两组共有的比较支持；是否提供证据关联、是否加入故事或不同结局，应分别在未来研究中操纵，避免把多个变化归因于对象化。

| 候选贡献 | 当前基础 | 本阶段交付与边界 |
| --- | --- | --- |
| 可操作的 GPU 资源与数据流表示 | 既有 GPU/SM 可视化与解析模型 | 三场景交互原型；对照使用相同模型与动作；有效性待测 |
| 从预测到后果再到解释的任务循环 | 升级预估、故事与经营目标 | 相同起点下调整、重置、比较，记录预测和理由；不提前标推荐路线 |
| 隔离表示效应的评估材料 | 机器可复算教学规则 | 独立专家审核的未见任务、盲评分规则和行为数据；目前不是已验证题库 |
| 对沉浸与理解的设计知识 | 来信与多结局 | 本轮只保留匹配的短任务背景；长剧情与经营选择保留在主游戏，另行评价 |

不把“首次将 GPU 做成游戏”“更多隐藏结局”“2.5D 机房”“用了真实品牌名称”作为核心创新。计算机体系结构游戏、程序语义游戏、硬件学习和 GPU 可视分析都有先例。[近邻与差异](hci-related-work.md)

## 3. 优先优化的交互：操作、观察与解释

### 3.1 三场景最小版本

独立探索实验台位于 `web/game/lab/`，不依赖经营存档、解锁或挂机。短任务提供目标；玩家观察初始运行，提交或跳过预测，在共同的试产点数约束内选择资源调整，运行后比较成本分解，再留下解释。可以重置与重新尝试。试产点数是虚构的教学分配单位，不是芯片面积、功耗或实际价格。

| 场景 | 教学目标 | 操作与可检查事实 | 不应教出的万能规则 |
| --- | --- | --- | --- |
| 计算受限 | 计算成本对资源变化的响应，总时间由多项组成 | 比较计算资源与搬运资源调整；查看分解 | 计算资源翻倍必定使总时间减半 |
| 带宽受限 | 数据搬运可能限制性能 | 同负载下比较资源调整；检查外部流量与有效带宽 | 带宽升级对每个负载总是最好 |
| 数据复用 | 缓存收益依赖复用与工作集，容量和带宽不同 | 在复用/流式场景各自基线上分别比较缓存调整，不直接比较两场景吞吐 | 缓存容量增加必定让所有任务变快 |

界面对象是教学隐喻。动画表达模型中的计算与数据搬运，不宣称逐周期重放真实 GPU，也不把动画中的距离、块数或运动速度当成额外测量。必须让两种表示接触相同数字、参数定义、比较结果和模型解释。

### 3.2 两种表示与比较控制

- **O：对象化交互表示。** 通过命名的计算、存储与数据流对象选择资源；所有操作同时可用键盘完成。
- **A：抽象交互表示。** 通过中性参数、表格或成本图选择同样资源并获得同样反馈。

两组都能运行、重置、在相同试产点数限制内改变相同参数、查看原始事实、比较和解释。资源点数按可选等级序号相加，每场景上限为基线点数加 2；降低资源可释放点数。这个约束只服务于有取舍的操作，不校准现实硬件成本。若 O 同时增加新反馈、答案提示、教程内容、预算或可执行动作，应先补齐 A；无法匹配时只能评价该设计组合，不能归因为纯表示效应。形成性版本可自由切换以发现问题；受控观察使用固定条件入口，禁止同一参与者跨条件学习。固定 URL 选择界面不是随机分组。

设备比较固定负载、初始硬件和其他参数，只改变一个声明的因素，保留它正常引起的派生影响。计算资源可能同时影响现有模型中的请求驻留，因此必须报告所有改变的分项，不能把总收益全部归因于算术吞吐。若一次更改多个因素，只评价整个配置差异。

### 3.3 模型与研究设施的边界

探索原型使用现有解析教学模型并保存模型身份，不是新的实测 GPU 执行器。现有 GPU 城市、SM 仿真和经营层没有统一执行时钟；本轮不声称从订单下钻到同一次真实 GPU 指令。模型显示、动画和用户操作的真实时间分别记录，不用模拟周期充当用户参与时长。

本地原型事件导出支持工程重放和形成性观察；正式的同意流程、分层随机化、独立测验、延迟追踪、研究数据管理仍未实现。下载一次 JSON 不等于已完成正式研究基础设施。

NVLink、PCIe、IB、机柜目前属于商业层规则，没有链路拥塞、集合通信或散热模型。第一轮主要硬件终点限定为三场景真实覆盖的**计算、带宽和缓存复用**。有限延迟隐藏、重叠与矩阵单元只作为当前计算公式的边界说明；若没有匹配教学与独立题目，不纳入主要测验。网络、机柜和软件生态进入学习终点前须补充相应机制、验证和同等暴露。

## 4. 指标：一个主要终点，其余各有职责

所有人类指标均为待采集。软件测试和脚本策略用于工程验证，不属于人类样本，也不证明学习或趣味性效果。下列正式测量规模为待专家审核的目标，三场景试运行只检查可行性。

### 4.1 主要、解释性与风险指标

| ID / 地位 | 要回答的问题 | 操作定义与分母 | 采集时间 |
| --- | --- | --- | --- |
| M1 / **唯一主要终点** | 能否解决未见过的硬件情境？ | 8 个未见情境，每题“瓶颈判断＋干预选择或结果预测”各 1 分；`100 × 正确小题数 / 16` | T0 前测、T1 即时后测；T2 延迟另作次要结果 |
| M2 / 关键解释性次要 | 是否真的理解为什么？ | 4 个独立提示，每题 4 项各 1 分：正确瓶颈、干预→资源→性能机制、条件改变后的反事实、边界/无效替代；`100 × 总分 / 16` | T0、T1、T2 |
| M3 / 延迟次要 | 理解是否保留？ | 第三套平行题的 M1、M2；分别报告 T2 组间差异及 T1→T2 变化，不只报保持率 | 第 7 天，允许 ±2 天 |
| M4 / 风险诊断 | 是否学到了错误的“万能规则”？ | 6 个专家审核边界题，区分正确、明确错误与不知道：错误数/6、不知道数/6；另报“前正确→后错误”数/前测正确目标数，分母 0 记 NA | T0、T1、T2 |
| M5 / 探索性信心 | 是否过度自信？ | 对 8 个干预回答填答对概率 `p`，Brier=`mean((p-y)^2)`；同时报准确率与 `mean(p-y)` | 三次测验 |

“迁移”首先指计算、带宽与缓存复用在新工作负载、参数或表面情境中的概念迁移，不等同于远领域迁移、实际 CUDA 优化能力或真实公司经营能力。正式题库由独立硬件专家审查，不能只用游戏代码给自己的教学效果出答案。[题库草案](hci-assessment-draft.md)

公开草案中的公式题首先用于演示计分、核算答案和检查题意，属于近迁移/规则应用材料。正式 M1 至少一半情境应改变表示或问题结构，例如提供未见的时序图、访存统计表及约束变化，并由独立证据或专家确认答案；不只替换同一道公式题的数字。题库冻结时预先区分这两个子集并分别报告，若效果只出现在换数值的题上，结论也只写近迁移。实际 CUDA/profile 能力需要另有真实任务和参考数据验证。

M2 由两位不知道参与者分组的评分者独立评分。先在不进入正式样本的材料上校准评分规则，冻结可接受答案与分歧处理办法；报告一致性及置信区间，不能只展示协商后的最终分数。总分可报告绝对一致型 ICC，逐项等级可报告加权 κ；选型和参数在收集前写清。

M5 题数少，个体结果不稳定；Brier 同时受到知识正确性和信心水平影响，不称为纯粹的元认知能力。若研究模型边界辨识，另用独立来源判断题评价，不把会读一个免责声明等同于理解真实性。[信心测量原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC6390881/)

### 4.3 商业选择与技术题分别评分

客户独家、公开接口、采购合作或团队并购没有普遍正确的伦理或经营路线。对这些决定只作探索性理由编码：是否说清目标与约束、考虑不同角色、区分短长期后果、引用证据并承认不确定性。不要按“选中了作者喜欢的结局”打分，也不混入 M1 硬件知识分数。

利润、通关率、破产率、结局数量、升级速度和点击次数用于平衡、行为或可用性分析。游戏规则本来就会影响这些值，因此不能拿它们直接证明真实决策能力或学习效果。

## 5. 正式实验：先隔离交互机制

### 5.1 两组核心比较

| 条件 | 相同部分 | 操纵部分 |
| --- | --- | --- |
| O：对象化交互 | 模型、起点、任务背景、动作、参数范围、事实、教程、运行/重置、比较与解释、学习窗口 | 资源以可选择的 GPU 对象与数据流关系呈现 |
| A：抽象交互 | 同上 | 资源以中性参数与抽象成本表示呈现 |

**主要比较为 O−A，唯一主要终点为 T1 的 M1。** 它估计在这套匹配界面和任务中对象化表示的效果；不单独证明故事、VR、实体操纵或整个经营游戏有效。

两组均使用共同的研究引擎，抽象组也能主动操纵系统。反事实比较与解释支持在两组保持一致。第一轮不加入无交互阅读组、故事开关或证据链开关，避免把表示、行动能力和信息量混在一起。未来若研究这些因素，应另设对照并重新规划精度。

当前网页固定条件 URL 仅限制表示切换；随机分配与分层应由预先冻结的外部研究流程执行和记录，不能称网页已经实现随机实验。

### 5.2 一次参与流程

建议试运行版本约 70–85 分钟，另有自愿继续的 5 分钟；正式时长在先导后冻结：

1. 告知研究、取得同意、记录既有 GPU 与游戏经验，约 5 分钟。
2. T0：平行题本的 M1 与 M2，以及边界题，约 15–20 分钟。
3. 正式研究通过独立流程分层随机分配 O/A；打开相应固定条件入口，共同操作介绍约 5 分钟。
4. 固定 25 分钟研究体验：三个标准场景、预先冻结的共同诊断机会及自由探索。各组的事实、预算、起始状态、随机条件与最长接触时间匹配。
5. T1：新的平行题，约 15–20 分钟；不能打开游戏或互联网，各组获得相同的必要公式表。
6. IMI、RTLX 与简短访谈，约 5–10 分钟；固定顺序，避免不同组测验前接受不同问卷提示。
7. 可选 5 分钟继续体验，报酬不以继续为条件；随后结束。
8. T2：7±2 天后第三套题，记录期间是否接触相关课程或重新使用工具。

研究模式使用同样的标准快照、关闭离线收益和自动跳过内容的便利入口，减少纯挂机、反复点击与等待解锁对条件比较的干扰。标准快照不是对主产品的线性关卡改造，正式参与者也不需要集齐结局或按照指定购买顺序通关。

F1/F2/F3 三套题覆盖同样知识点和难度，跨 T0/T1/T2 轮换。题本名字不与实验条件 O/A 混用。先用认知访谈与试运行检查题意、难度、地板/天花板和阅读负担，再冻结正式材料。测试草案公开不等于正式答案已泄漏可用；正式研究需使用未曝光的冻结题本。

### 5.3 分析与样本量

主要分析预注册为 T1 M1 的 O−A 差异，双侧 α=.05，按参与者随机分组进行意向治疗分析。采用 ANCOVA 调整 T0 M1、题本及预先规定的分层变量，报告调整后的百分点差、效应量和 95% CI。题目不是独立参与者，不能把 16 个小题乘进样本量。需要时用带参与者和题目效应的模型作敏感性分析。

主要检验通过后，再按预注册顺序检验 O−A 的 M2；否则 M2 仅作解释性估计。延迟、体验、信心和日志结果明确标为次要或探索性，报告估计及不确定性，不选择最显著的一项改称主要结论。主要模型不调整随机分组后产生的活跃时间、点击数或证据使用量，也不因参与者没有使用新功能而剔除。

示例：若预先认为 **12.5 个百分点，即 16 小题多答对 2 题**值得关注，且总分 SD 为 25 个百分点，则对应 `d=.5`。双侧 α=.05、80% 功效的常规两组近似约需 **64 人/组**；O/A 共 128 名完成者。若按 20% 失访预留，约招募 160 人。这些是显式假设下的规划示例，不是既有估计、固定要求或足够功效的保证。

正式样本量要按最低有意义差异、方差、前后测相关、题目难度、随机化结构及失访情况进行功效模拟。先导的主要职责是查问题、估计测量尺度，不用十几人的不稳定大效应替正式研究压低 N。

明确区分：看到了题目但空答/跳过按题规计 0；整次后测缺失、退出或技术失败属于缺失，不直接填 0。报告各组缺失原因和失访率，预先规定插补及敏感性分析。访谈与日志可解释模式，不能把相关关系改写成因果中介证明。

## 6. 现在必须补的工程与研究基础

| 优先级 | 改进 | 完成证据 |

| P0 | 三场景共同模型与操作等价 | O/A 对同一输入与行动返回相同结果；查看全部派生影响 |
| P0 | 模型、对象和反馈一致 | 同一配置对应相同事实；动画仅作声明过的教学表示 |

## 7. 分阶段执行与停止条件

1. **原型与专家审查。** 先完成三场景 O/A、模型解释、同输入等值检查与本地导出；请独立 GPU 教师和测量研究者审查目标、答案及表示偏向。专家审查不是统计验证。
2. **约 8–12 人形成性试运行。** 按目标学习者背景有目的地覆盖不同经验，允许主持人记录求助和访谈；检查操作、趣味线索、误解、时长与日志。数字是问题发现的规划起点，不是功效样本量。
3. **修订后冻结。** 修改玩法和题目；无法独立完成、两组信息不匹配、关键日志丢失或模型表达误导时，先修复再复测。先导材料与参与者不进入正式效果样本。
4. **正式研究准备。** 确定主要差异的实际意义、完成平行题与盲评规则、模拟功效和失访、完成适用伦理与同意、预注册分析与停止规则。当前原型没有完成这些步骤。
5. **正式随机实验与追踪。** 按预定样本和规则招募，报告技术失败、缺失、组间差异和置信区间，不根据显著性停招。

趣味性提高但迁移未提高、迁移提高但体验负担增加、或新增误解，都需要照实报告。未显著不等于等效；若转向非劣效主张，应事先定义界值并重新设计研究。当前最重要的交付是可完整体验的小原型与能发现问题的试运行，不是更多题材或结局。

## 8. CSCW 的后续独立方案

如果确定要投 CSCW，增加真实玩家间的任务依赖：硬件、软件、运维角色分别掌握不同约束，共享预算与交付目标，通过共享证据协商。可以先做同地共同操作与角色材料，不必先建大规模在线多人服务；但多人界面本身不是协作研究贡献。

建议问题：**共享、可检查的反事实证据如何改变跨角色架构决策中的知识交换、责任协商和共同理解？** 比较相同信息与任务下的普通共享结果和可关联证据界面。

| 团队指标 | 定义与边界 |
| --- | --- |
| 约束满足的决策质量 | 达到全部硬约束的团队任务数/团队任务数；多种可行方案可同时正确，不只奖励利润 |
| 共同理解 | 分别测每位成员对瓶颈/约束的准确理解，再报成员之间一致性；一致的误解不能算成功 |
| 协商过程 | 编码提出证据、质疑假设、澄清角色约束、更新方案与解决分歧；报告盲评/编码方法和反例 |
| 协调成本 | 达成可执行方案的真实时间、返工与未解决冲突，结合质量解释，不以最快为唯一目标 |
| 个人迁移 | 协作之后每位成员独立完成新题，防止只是一人替团队解决全部问题 |

随机化与功效以团队为单位，成员数据按嵌套结构分析，不能套用单人研究的 N。Crystallize 的 CSCW 正式论文提供了任务相互依赖、真实协作过程与个人学习一起测量的可借鉴案例；当前 NPC 对手不能充当这种实验中的合作成员。[Crystallize 原文](https://www.cs.cornell.edu/~eland/papers/cscw2016.pdf)

## 9. 论文组织与近邻定位

按“真实困难 → 交互机制 → 实现与边界 → 对照实验 → 推广条件”组织。主要结果图优先展示 M1 的组间差异及区间、M2 的解释类型与区间、延迟/新增误解；访谈和过程图解释学习者如何形成或修正判断。兴趣与性能图不能替代主要知识证据。

最应处理的近邻包括 Reduct（CHI 2017，语义操作与近迁移）、LearnIoTVR（CHI 2023，硬件到系统学习）、Storytelling Alice（CHI 2007，兴趣与学习差异）、Crystallize（CSCW 2016，任务依赖与协作）、Academical（FDG 2020，交互故事与理由质量），以及 Daisen（EuroVis/CGF 2021，GPU 运行证据的可视分析）。完整书目信息、真实评价方法和反向证据见[学术近邻](hci-related-work.md)。

这些文献帮助限定主张，不能替本项目提供效果量或录用保证。若只有“用户觉得好玩”，写体验或形成性发现；若要写“促进系统理解与迁移”，就用独立任务和适当对照取得对应证据。
