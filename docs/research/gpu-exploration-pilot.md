# GPU 三场景探索实验台：形成性试运行手册

日期：2026-10-19。状态：可本地操作的工程原型与研究准备材料；没有参与者数据或教学有效性结果。配套：[研究方案](hci-publication-plan.md)、[机器可读协议](hci-metrics-protocol.json)、[题目草案](hci-assessment-draft.md)。

本阶段检验的是：目标学习者能否操作、理解反馈并愿意继续探索，以及我们是否能可靠观察这些过程。约 **8–12 人**是问题发现的规划起点，不是检验效果的功效样本量，也不承诺达到饱和。

## 启动与条件入口

在仓库根目录运行：

```bash
npm start
```

默认端口为 4173：

| 用途 | 地址 | 允许的解释 |
| --- | --- | --- |
| 自由探索 | <http://127.0.0.1:4173/web/game/lab/> | 可切换表示，适合开发演示；不能当作组间随机实验 |
| O，对象化表示 | <http://127.0.0.1:4173/web/game/lab/?condition=objects> | 固定表示，适合受控观察；URL 没有随机分配参与者 |
| A，抽象交互表示 | <http://127.0.0.1:4173/web/game/lab/?condition=abstract> | 同模型、事实、动作、比较与解释；固定表示 |

先导可分别观察两种固定入口，记录分配方式、经验与先后顺序。若另设同一人体验两种界面的访谈，应在主要无提示任务之后，明确记录顺序与此前暴露，只用于比较偏好、发现问题。不能将跨条件学习后的得分当作独立组间效果。未来正式研究由预先冻结的外部流程进行人级随机分配，网页自身不实现随机化。

不需要经营存档、等待解锁或输入姓名。当前事件仅留在该标签页内存，由操作者主动下载 JSON；不向服务器上传。刷新或关闭标签页会丢失未导出的会话。页面导出不包含知情同意、正式题本、联系信息管理或延迟测验服务。参与者研究按所在机构适用的伦理与同意流程执行，本手册不代表已经批准招募。

## 先核对模型，再观察参与者

请至少有独立 GPU 教师/研究者和熟悉 HCI/测量的研究者审查，记录姓名或研究角色、版本、日期、分歧与处理结果：

- 三场景确实覆盖计算、搬运及复用机制，且界面没有隐藏与叙事相冲突的规则。
- 相同输入在两种表示中给出完全相同数值、参数范围、模型说明、比较和解释能力。
- 对象图、流向和动画与解析结果一致；不暗示实测芯片布局、链路宽度或逐周期执行。
- 题目答案由独立核算和专家理由支持，不只复述游戏引擎输出；测试不偏向任一学习界面。
- 题目阅读量、数学负担、提示量、时间和可用帮助可比较；没有把“会使用页面”误记为系统理解。

专家审查解决机制与内容问题，不等于已完成统计验证。条件的信息不等价、模型错误或关键导出丢失时，先修复再开展参与者观察。

## 三场景与教学机制

模型为 `analytical-compute-memory`，当前版本由导出中的 `provenance.model` 与 `exportInfo` 确认。参数未经真实 GPU 测量标定；结果为逻辑周期，不预测实际 CUDA、互联或能耗。

| ID／任务 | 初始配置及工作负载 | 观察与操作目标 | 重要边界 |
| --- | --- | --- | --- |
| `compute`／夜班校验 | `fp32`；4 个计算单元、4 组 DRAM、无 L1 | 比较单独增加计算单元或搬运通道后的周期分解 | ALU 改变也可能影响请求驻留；不能把所有收益归于计算项 |
| `bandwidth`／沿海数据站 | `stream`；32 个计算单元、1 组 DRAM、无 L1 | 单独增加计算或 DRAM，检查数据搬运变化 | 多个参数同时变化仅能评价配置整体；流式模型仍可有少量复用 |
| `reuse`／旧城影像修复 | `conv`；64 个计算单元、1 组 DRAM、无 L1 | 单独增加 L1，检查命中、外部流量与总时间 | 缓存容量通过工作集和复用影响模型；增加缓存不等同于增加外部带宽 |

计算资源可选 1、4、8、16、32、64 个，DRAM 为 1–4 组，L1 为 0–128 KiB，每级 32 KiB。这些是教学资源配置，不是实际产品规格。若比较复用与流式缓存收益，应在两场景各自基线上分别作单因素试验，再解释差异；两场景的初始计算/DRAM 资源也不同，不能直接将总吞吐差归因于复用。

两种表示共享有限试产点数：资源等级在选项列表中的序号相加，每场景上限为基线点数加 2；计算/带宽场景上限为 6，复用场景为 7。降低资源可释放点数，超出限制的调整被拒绝。点数是虚构的教学分配单位，不是芯片面积、功耗、实际价格或真实性能成本比。请观察玩家是否理解约束，不把记住点数表当成 GPU 理解。主游戏中的经营与伦理路线继续允许多种合理结局，不进入硬件正确率。

## 一次形成性观察

建议预留约 45–60 分钟，时长由试运行反馈修订，不是正式实验的冻结时长。

1. **说明与基线，5–10 分钟。** 完成同意与记录安排，使用研究代号。记录编程、组成原理、GPU 与游戏经验。不要将姓名写入游戏自由文本。选用经专家审查的独立小题，不展示答案。
2. **共同操作介绍，约 3–5 分钟。** 只介绍如何选择资源、读试产点数限制、运行、重置、读逻辑单位与导出，不演示哪个升级最优。两种界面的介绍目标与帮助量相同。
3. **三个场景，约 20–25 分钟。** 依次或按预先记录的平衡顺序完成下表任务。允许不知道、跳过预测与失败；主持人不提示瓶颈，必要帮助记录逐字提示与发生时间。
4. **独立新题，约 5–8 分钟。** 关闭实验台，使用另一套中性题面。主持人先收答案再追问；这轮只检查测量是否能用，不进行显著性效果结论。
5. **体验与访谈，约 8–12 分钟。** 先问开放问题，再展示另一表示征求偏好时要标注额外暴露。正式 IMI/RTLX 版本与中文适配尚需固定，试运行口头评价不得称为验证量表得分。
6. **导出与核查。** 下载 JSON，按匿名研究代号由研究者单独保管映射；确认文件能解析、任务操作顺序与观察表相符。原型不会自动上传或备份。

形成性观察可以使用轻量回顾或出声思考，记录它可能改变推理。未来正式效果研究不在学习过程中要求持续出声思考。

### 三场景共同任务清单

每场景使用同一任务措辞，避免告诉参与者选择哪个路线：

- [ ] 阅读任务，说明当前目标；不要求猜作者期望答案。
- [ ] 查看初始配置、点数限制与分解，指出哪些数据看懂、哪些看不懂。
- [ ] 选择一次调整，运行前记录预测或明确跳过。
- [ ] 运行，查看与场景固定基线的比较；说出实际变化及依据。
- [ ] 至少尝试一次只改变一个资源的比较；若参与者不这样操作，先记录再询问，不悄悄纠正。
- [ ] 保存一次运行后的解释；允许解释“不知道”，不把文字长短当质量。
- [ ] 重置并确认回到本场景基线；先前运行仍在会话导出中。
- [ ] 标记求助、错误、卡住、误解、主动探索与中断；完成不等于理解。

原型的预测是相对**该场景固定初始基线**，不是相对最近一次运行。改变资源会清空当前草稿预测与当前结果有效标记，需重新提交；每次运行保存当时预测与配置，解释归属具体运行。后看结果再填的预测不能当作事前预测，需按事件/标记识别。没有提交预测的运行仍是有效探索，正式是否要求提交应在研究冻结时统一规定。

## 记录表与判据

每个场景记：研究代号、表示、版本、开始/结束、首次无帮助运行、有效单因素比较、提示次数与内容、解释原话、错误观念、操作障碍、是否主动再试、导出是否完整。按问题的任务影响与可重现性分级，不只统计点击。

进入正式研究前至少满足：两种表示的模型与动作等价；关键操作能无主持人持续讲解完成；反复出现的机制误解得到修订；新题能区分知识与算术/阅读障碍；日志与观察可核对。没有预先样本就不能宣称“8/10 完成率已达标”，应报告实际分母、帮助与不确定性。

## 八个中性访谈问题

1. 你刚才想解决什么问题？哪些地方让你改变了最初目标？
2. 你根据哪些信息决定第一次调整？当时还有哪些不确定？
3. 哪个结果符合你的预期，哪个让你意外？你如何解释？
4. 页面上的哪些内容帮助了判断？哪些内容容易被误解？
5. 如果换一份工作，你会先检查什么？什么情况下刚才的方法可能失效？
6. 哪一段让你想继续尝试，哪一段让你想停下来？是什么原因？
7. 有没有你想做、但页面不允许或找不到的操作？
8. 如果你向另一位同学解释这里发生了什么，会怎么说？还有什么需要查证？

不问“实体化是不是更直观/有趣”等引导问题。偏好与解释可以不同：喜欢对象界面不代表答题更准确；抽象界面操作快也不代表理解更深。

## 导出文件能与不能回答什么

当前事件包含 `sequence`、`type`、`elapsedMs`、`scenarioId`、`presentation`、`configurationRevision` 和 `payload`。会话保存初始 `condition`、当前 `presentation`、模式、切换标志、模型与场景版本、基线、配置及运行记录。运行记录包含变化资源、`single-factor`/`multi-factor` 比较类别、预测快照、成本结果及解释修订。自由切换被记录并标记；`exportInfo.randomized` 与 `controlledAssignment` 均为 `false`。

`elapsedMs` 是会话相对的真实单调毫秒；逻辑周期属于模型输出。相对真实经过时间可能包括阅读、失焦或离开电脑，**不能直接解释为主动投入时长**。当前本地事件不等同于完整研究 schema；没有记录到的行为属于未知，不能补为零。下载后重新打开产生新会话，不与旧相对时钟直接相减。

正式研究还需要独立任务与题本、真实分配记录、同意版本、缺失与技术失败处理、标准邀请/前台活动记录、保留与退出安排及延迟联系流程。确认这些前，本原型适用于工程验证与按规定组织的形成性试运行。
