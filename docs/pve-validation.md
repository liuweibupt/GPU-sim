# 创业赛与性能模型验证

日期：2026-10-15。入口 `/web/game/pve/`，原工坊和 GPU 工作台继续保留。

## 自动验证

- `npm test`：223 项通过，包含 10 项性能模型、18 项创业竞赛、16 项金融账本，以及原工坊与仿真工作台检查。
- 模型检查覆盖周期与流量分解、单 ALU 基线、有限并行收益、工作集/缓存关系、带宽、延迟隐藏，以及 Tensor/TMA/TMEM 的负载选择性。
- 创业赛检查覆盖对手自主研发、第一桶金与 GPT-3/商业首单、并列判定、共同离线时钟、破产冻结与不同帧划分的一致结果。
- 金融检查覆盖一次 IPO、20% 稀释、股数守恒、回购费用/流通股/运营储备限制、欠款偿还、破产，以及保存恢复不把融资计为营业收入。
- `npm run validate`：七份已有仿真轨迹通过。
- `npm run build`：静态构建包含三个页面、共享模型与原创 Lisa SVG。

## 可复现的完整经营策略

运行 `npm run benchmark:pve`；策略和初始条件在 `scripts/benchmark-pve.mjs` 中公开，确定性结果保存在 `docs/pve-balance.json`。

| 策略 | 初始条件与操作 | 结果 |
| --- | --- | --- |
| 主动、均衡投资 | 零现金，一颗 ALU；每模拟秒参与一次，按公开顺序补齐硬件，达标 IPO 与训练 | 569 秒（约 9.5 分钟）由玩家拿下商业首单 |
| 完全挂机 | 玩家不投资、不点击；对手同样从零自主发展 | 1,334 秒（约 22.2 分钟）灰盒实验室率先交付 |
| 只扩计算工位 | 合法经营积累现金后 IPO，仅购买 ALU/时钟并停止手动参与 | 821 秒（约 13.7 分钟）触及破产线 |

这些路径没有注入起始资金、硬件或欠款；证明当前规则能产生获胜、落后与真实经营失败。它们不保证所有投资策略都平衡，后续改参数或模型需重新运行策略检查。

## 浏览器检查

在 Chrome 实测桌面 1440 px 与手机 390 px：

- Lisa 在玩家不投资时实际增加 ALU 与缓存；暂停会冻结全场时钟。
- 模型窗口可以切换负载并查看周期分解；原工坊也展示当前任务的解析周期。
- 股价窗口可切换三家公司；未上市时明确标为估值参考。
- 从合法经营状态 IPO 后持股为 80%、流通股为 250；回购 10 股后流通股为 240、持股约 80.6%，融资不增加营业收入。
- 非整数回购被拒绝；破产后计算、IPO 与研发关闭，界面不再承诺继续扣费或可研发。
- 重开竞赛不改写原工坊存档；离线返回同时显示三家公司的经营收入变化。
- 手机页面无横向溢出，工坊到创业赛的链接正常；无 JavaScript 或页面资源请求错误。
