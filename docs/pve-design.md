# 算力创业赛 · 黄Sir vs Lisa

## 一句话企划

从一颗 ALU 开张，接单、扩厂、融资，与持续成长的对手争夺下一次计算浪潮。
玩家经营黄Sir的工坊，Lisa 与虚构的灰盒实验室分别经营自己的公司。
三家公司同一时刻起步，各自赚钱、研发与交付，不共享现金、硬件或任务队列。
PvE 是一场持续的挂机商业竞赛；对手不会等待玩家购买升级后才行动。

## 页面与边界

- 独立入口：`/web/game/pve/`；页面名为「算力创业赛」。
- 发布地址：[GitHub Pages](https://liuweibupt.github.io/GPU-sim/web/game/pve/)。
- 原算力工坊 `/web/game/` 与 GPU 工作台 `/web/` 继续保留并提供返回入口。
- 创业赛使用独立本地存档，不读取或改写原工坊的资金、硬件与应用进度。
- 主角统一称为黄Sir，对手统一称为 Lisa；灰盒实验室是虚构的第三家公司。
- 人物形象与技术史提供创作灵感，客户、对白、资金、收益与赛事均为游戏设定。
- 股价属于游戏内模拟，不展示真实证券行情，也不构成产品性能评测。

## 故事开场

赛博史官收到三份开业公告：同一条街，三间车库，三颗刚通电的 ALU。
客户源源不断地带来浮点订单。有人先扩充工位，有人先解决数据供给。
当小单变成矩阵业务，新的目标出现：谁先把模型训练变成一笔真正交付的订单？
史官记录的是每个公司的选择与先发时刻，胜负由持续经营产生。

黄Sir：「客户已经排队了。先把第一块缓存的钱挣出来。」
Lisa：「你在算今天的单，我也在准备明天的生意。」
灰盒实验室：「把数据送到工位，也是生产力。」
赛博史官：「三家公司同时开张。时钟开始。」

## 三个先发时刻

| 里程碑 | 达成条件 | 记录意义 |
| --- | --- | --- |
| 第一桶金 | 累计经营收入达到 $1,000 | 比较接单与早期扩张能力 |
| GPT-3 时刻 | 硬件条件齐备，完成 20,000 单位训练 | 比较经营与模型投入的安排 |
| 首单商业化 | 模型完成后再交付 10,000 单位订单 | 首先到达者赢下本场竞赛 |

累计收入包含已经花掉的钱；IPO 融资不计入第一桶金。
每个里程碑分别记录最早到达者，其他公司仍能继续完成自己的目标。
同一模拟秒到达时明确显示并列，不能由公司列表顺序决定冠军。
商业首单冠军产生后保留记录，公司仍可继续经营、扩张与观察股价。
GPT-3 的名称用于应用主题，游戏工作量不对应真实训练规模、成本或训练时长。

## 经营与应用仍是两条线

**硬件线：** 普通订单带来经营收入，收入里程碑与前置部件开放新图纸。
现金用于购买组件；资本融资可以帮助付钱，但不能越过研发收入门槛。
硬件逐步扩展流式、卷积、矩阵、异步搬运与注意力等客户任务。

**应用线：** 研发准备达到要求后，玩家决定何时启动模型项目。
GPT-3 项目需要 ALU 7 级、L1 2 级、DRAM 1 级、L2 2 级、调度 2 级、Tensor 2 级、HBM 1 级。
初始 ALU 不算升级级数，因此 ALU 7 级表示共八个计算工位。
训练与商业交付期间，70% 算力投入项目，30% 继续接日常订单。
运营成本持续发生；可以先存储备现金，也可以提前启动争取先发优势。
原工坊的 AlexNet 仍位于其应用线的较后期，不作为创业赛开局任务。

## 三种经营性格

- **黄Sir：** 由玩家决定每笔投资、上市时机、回购数量与项目启动时机。
- **Lisa：** 均衡发展计算、缓存与供数，自主融资并向矩阵业务和模型交付推进。
- **灰盒实验室：** 优先投资缓存与显存，以不同的建设顺序竞争同一批先发时刻。

对手拥有真实推进的游戏账本和机器状态，展示现金、收入、硬件与项目进度。
对手同样受购买价格、前置条件、营业收入、运营成本和破产线约束。
玩家可以手动参与计算；同一时刻连点不会凭空获得无限收入或训练进度。

## 负载决定硬件的价值

| 部件方向 | 游戏中的主要作用 |
| --- | --- |
| ALU、时钟 | 扩展通用浮点计算能力，同时增加运行负担 |
| L1、L2 | 改善重复使用数据的任务，缓存复用影响订单效率 |
| DRAM、HBM | 改善数据供给，支撑更大的数据流与后期任务 |
| 调度器 | 组织并行工位与客户请求 |
| Tensor Core | 加速矩阵、卷积与相关模型任务 |
| TMA | 改善异步搬运与相应的计算流水线 |
| TMEM | 改善后期矩阵中间数据与注意力任务 |

市场订单存在需求上限：基础为 $2/秒，每多开放一类负载增加 $3/秒，基础上限 $17/秒；系统与生态投资可额外增加最多 $12/秒的客户预算。
上限约束自动营业的长期收入；点击参与计算提供主动经营帮助。
机器能算更多，不表示客户一定会买更多；只扩充同一种工位也会产生持续成本。
性能从运算量、数据量、工作集与复用推导；`T = C + M − overlap × min(C, M) + L` 分解计算、搬运与等待代价。
缓存容量与工作集决定可复用数据的命中机会，带宽与调度决定供数，TMA 增强重叠，TMEM 减少中间结果溢写。
模型采用未经过真实芯片实测校准或机器学习训练的归一化教学参数，界面公开瓶颈与输入，不声称真实 GPU 性能。

## 资本工具箱

另有独立的**系统与软件生态**投资区：PCIe、NVLink、IB 合作采购或网络团队收购、机柜，以及 CUDA 工具链、加速库和开发者生态。生态提高客户溢价与需求上限，系统改善训练和商业交付；新增持续费用与设备账面价值进入同一金融账本。合作采购资金门槛低、费用高，收购资金门槛高、费用低，二者是本场互斥的采购策略。对手也会在基础硬件计划完成或商业化后根据现金储备自主投资。NVLink 自研、Mellanox 收购的历史区别及完整规则见[系统研发与软件生态](systems-business.md)。

公司开局有 1,000 股，全部由创始人持有，尚未上市。
累计订单收入达到 $600 后，可以进行一次 IPO，向市场新增发行 250 股。
首次上市后总股数为 1,250，创始人仍有 1,000 股，持股比例降至 80%。
发行价由融资前的净资产和预计收入生成，最低 $1/股；现金按发行价乘股数增加。
融资款进入公司现金，不增加订单收入、研发累计收入或第一桶金进度。

上市后，可以按当前价格回购流通股，实际减少现金并提高创始人持股比例。
回购数量必须为正整数，不能超过流通股；有运营欠款时先偿债。
回购后至少保留 10 秒运营费用；这个最低限额不保证能度过整个训练期。
回购股份计入库存股，不再计入流通或在外股数；回购全部股份也不能再次 IPO。
按同一估值连续发行再全部回购不会赚出额外现金，没有反复融资的套利循环。

## 模拟股价窗口

可切换查看三家公司的每股估值曲线、公司估值、创始人持股和流通股数量。
未上市时标为「估值参考」；公司估值等于每股估值乘在外股数。
估值由现金、硬件账面价值、运营欠款和预计经营收入产生，没有随机跳涨奖励。
股价上涨不会自动变成现金；只有订单收入与实际发行融资能为账本增加现金。
曲线每至少 5 秒采样一次，最多保留 120 个点，避免挂机存档无限增长。

## 运营成本与破产线

运营费用按机器功耗与部件数量增长，包含非线性扩张负担。
初始一个 ALU 的预计收入约 $0.71/秒，运营成本约 $0.16/秒，新手有正向经营空间。
每次结算先用本次营业收入偿还欠款，再用现金支付运营成本；现金不足才增加欠款。
现金用完不会立即破产，信用额度为 `min(2000, 250 + 累计经营收入 × 0.1)`。
欠款达到额度时公司破产，冻结接单、投资与项目，不能靠再次 IPO 复活。
界面显示净现金流、运营成本、欠款和破产线，让扩厂与启动训练的风险可见。
投资过快、忽视需求上限或在现金紧张时回购，都可能把扩张变成持续亏损。

## 保存与重开

当前浏览器自动保存全场进度，离线期间三家公司按同一时钟继续经营，最多计入 8 小时。
离线推进包含对手投资、项目和成本，不能只给玩家结算收入而冻结对手。
可以暂停全场查看局势，也可以重开创业赛；重开范围仅限这场独立比赛。
页面不引入在线匹配、真实证券交易、真钱消费或跨设备账号同步。

## 验证目标

检查独立存档、项目条件、订单账本、IPO 一次性、股数守恒、回购限制与破产冻结；完整从零策略应证明合理投资可以赢、对手自然发展、过度扩张会亏损破产。
同样的模拟时间按不同浏览器帧率推进，应得到相同账本与先发结果。
