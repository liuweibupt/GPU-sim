- 一组流式配置（32 ALU、一级 L1/DRAM/L2、四级调度器）在浏览器中显示：批次 96.8 模型 tick，外部读写 116 KiB，L1 命中 1/24；升级 ALU 预计收益四舍五入到 0.0%，升级 DRAM 约 35.0%。这是该教学配置的模型结果。
- 本机 Node 单次测量：100 次未缓存 GEMM 代表批次共约 10.3 ms；正常回放复用缓存，不逐帧重新仿真。这不是浏览器或所有设备的耗时保证。

## 工作集、瓶颈诊断与 HBM 替代修正

- 全量测试更新为 188 项通过，静态构建通过。新增覆盖三级工作集容量边界、订单规模固定、升级前后速率一致、延迟/带宽关键路径拆分、独立并发试算以及 HBM 停用 DRAM 购买与存档恢复。
- 同一组硬件（32 ALU、二级时钟、一级 L1/L2/DRAM/调度器、四级 Tensor），GEMM 输入工作集从 32 KiB 增至 64 KiB 时，L1 命中转为 L2 命中；在 64 KiB 用例上升级 L1 预计约 5.5%。512 KiB 用例超过一级 L2，升级 L2 预计约 17.1%；32 KiB 用例升级 L2 仍为 0%，保留容量已足够时的零收益。
- Chrome 实测大订单页面的 L2 提示为 17.1%，点击后顶部速率由约 3.9 增至 4.6。安装 HBM 后 DRAM 按钮禁用，显示“外部访存已由 HBM 服务”。展开诊断可见三项独立试算。
- 桌面 1440 px 和手机 390 px 无脚本错误或页面横向溢出。Node 单次测量：10 组最大 attention 代表批次及其三项诊断共约 118 ms；这些结果按配置缓存，不在每次绘制时重算。

前一节的固定 24 tile 与旧用例数值为 v1 接入记录，当前以按订单规模生成的 v2 批次为准。仿真仍使用教学参数，工作集大小变化不等于真实 kernel 地址轨迹。

同步远端 `a03aa1c`、`fc2ec01`。当前默认执行模型为解析模型，工坊可在运行时切换到 Tile 资源仿真；已有订单进度与模型选择均可保存恢复。创业赛继续明确使用解析模型，其经营策略基准仍为主动玩家 569 秒获胜、挂机对手 1,334 秒获胜、过度扩张玩家 821 秒破产。

审查并修正了两处资源仿真边界：

- 安装 Tensor 后保留 ALU 执行路径，对比纯 ALU 与最早完成混合调度，返回真实较快方案的完整事件与资源统计。避免较慢的 Tensor 池强制替代较快 ALU；`computePolicy` 记录选中的调度方式。
- L2/L1 端口分别设为 16,384/32,768 B/tick，维持与最高 16,384 B/tick HBM 一致的供数层次。高级 HBM 配置下，扩大 L2 不再因为命中更慢的端口而降低吞吐。
