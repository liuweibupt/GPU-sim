# 黄Sir的算力工坊

## 一句话企划

从一颗 ALU 开始接浮点数计算订单，把小作坊经营成 AI 算力工厂。
玩家也是「赛博史官」：见证应用需求与硬件能力各自成长，并决定下一笔钱投在哪里。
主角统一称为「黄Sir」，以原创的皮衣工坊老板形象登场，负责教程、剧情和吐槽。

## 页面与美术

- 独立网页：`/web/game/`，源文件位于 `web/game/`。
- 页面名：**黄Sir的算力工坊**；气质是深色机房、荧光绿电路、暖色游戏资金。
- 中央工坊从孤零零的 ALU 逐渐长出缓存、内存和计算模块，让购买产生可见变化。
- 顶部突出游戏资金、处理速度与完成订单；队列区显示持续经营的客户请求。
- 应用合约展示待交付的任务；硬件研发区另行展示部件、前置条件和发展记录。
- 主角对白短而有性格，不遮住队列、商店或当前任务。

## 核心循环

1. 客户持续提交计算请求，订单进入等待队列。
2. 工坊自动处理订单，获得游戏资金并积累经营规模。
3. 玩家点击参与计算，触发有冷却时间的短暂加速，等待时也能持续经营。
4. 用资金增建 ALU、购买缓存与内存，解决当前订单的瓶颈。
5. 自主选择是否接下大型应用合约，完成后领取资金和剧情奖励。

开局只有一颗 ALU，没有缓存，也没有 DRAM 或 HBM。
初始 FP32 订单由游戏抽象的外部输入供给数据，机器能工作，但不能缓存复用数据。
这表示工坊尚未购置存储部件，不表示真实 ALU 能脱离输入、寄存器和控制系统运行。
资金、价格、工作量与倍率均为游戏参数，具体数值以引擎实现为准。

## 两条独立的发展线

**经营与硬件研发线：** 完成普通订单持续赚钱，累计收入 `totalEarned` 与部件前置条件
决定研发选项何时开放；当前资金决定买不买得起。收入里程碑不会因购买升级而倒退。
硬件发展记录解释 ALU、缓存、调度、Tensor、TMA、TMEM 解决什么问题。
新硬件会扩展普通订单池，并改变不同工作负载的处理效率。

**应用与剧情合约线：** 从标量、向量、图形和物理任务逐步走向深度学习与大模型。
大型合约要求相应的工坊能力，完成后提供资金、剧情和成就感。
应用胜利不是购买硬件或解锁普通工作负载的前置条件；不接大单也能继续经营。

两条线通过资金与能力相互影响，不构成「过一关才允许研发下一代硬件」的单一关卡链。
玩家可以先投资硬件再挑战大单，也可以用现有设备慢慢交付，争取下一笔扩建资金。
硬件史提示与应用主题分开记录；部件上线、应用出现和玩家完成挑战并非同一个时间点。

## 三步新手教程

**先接第一单。** 黄Sir：「门口有人排队了。先别做发布会，把这几个浮点数算完。」

**再做第一笔投资。** 黄Sir：「第一桶金到了！加个工位，还是把常用数据放手边？」

**最后认识两条线。** 黄Sir：「接什么大单，你决定。研发什么设备，也由你决定。」

早期任务从小数算术起步，让玩家在进入 AlexNet 前经历并行计算与数据供给的成长。
升级区展示缺少的资金、经营里程碑或部件，应用区单独展示交付条件，减少混淆。

## 硬件研发线

| 部件 | 游戏作用 | 黄Sir的一句话 |
| --- | --- | --- |
| ALU | 增加基础并行计算能力 | 「一个人干不完？先加个工位。」 |
| 时钟 | 提高计算节奏 | 「拍子快一点，手别打结。」 |
| L1 Cache | 改善局部重复访问 | 「常用的东西，放手边。」 |
| DRAM | 增强数据供给与存储能力 | 「终于不用把客户的数据堆门口了。」 |
| L2 Cache | 进一步改善可复用数据供给 | 「同事们，别各自搬一遍同一箱货。」 |
| 调度器 | 改善任务组织与处理效率 | 「队伍排好，别让 ALU 等人。」 |
| Tensor 单元 | 强化适合矩阵加速的工作负载 | 「有些活，适合一整块一起算。」 |
| HBM | 支撑后期大吞吐任务 | 「算得快，也得喂得上。」 |
| TMA | 改善异步搬运任务 | 「搬数据这件事，也该有专人负责。」 |
| TMEM | 改善后期矩阵与注意力任务 | 「矩阵也需要自己的工作台。」 |

研发选项按经营规模和部件依赖逐渐出现，具体条件由引擎统一定义。
界面读取同一份配置，让显示条件与实际购买行为一致。
硬件可扩展流式、卷积、矩阵、异步搬运和注意力等普通订单，不要求先赢某个应用合约。
这些类别是游戏任务抽象，并不表示没有专用硬件就无法执行相应的真实算法。

## 应用合约线

| 阶段 | 应用主题与玩法 | 黄Sir的剧情对白 |
| --- | --- | --- |
| 小数事务所 | 标量浮点请求，认识接单、队列与收入 | 「小数点先站稳，工厂才能站起来。」 |
| 向量快递 | 一批数据重复同一操作，体验增加 ALU 的价值 | 「一件一件送太慢，整排一起走。」 |
| 像素工坊 | 图形计算主题，感受并行能力与数据供给 | 「客户说只画一张图，没说有多少像素。」 |
| 物理沙盒 | 多对象计算主题，观察调度与缓存投资 | 「球可以乱弹，订单不能乱排。」 |
| AlexNet · 2012 灵感 | 较后期的浮点卷积大单，检验并行 ALU、缓存与内存 | 「今天客户终于开始问：猫在哪里？」 |
| Transformer · 2017 灵感 | 序列与矩阵主题，继续扩展工坊协作能力 | 「客户说就预测下一个词。这句『就』最占预算。」 |
| 大模型训练 | 持续的大规模矩阵任务，检验后期产线 | 「参数越来越多，账本也得翻页了。」 |
| 长序列推理 | 更长上下文的注意力主题，考验数据流转 | 「它记得住这么长的话，我得记得住电费。」 |
| AI 工厂 · 2026 架空 | 综合大型交付，迎来工坊经营的终章 | 「从一颗 ALU 到一座工厂。下一单，拿来。」 |

AlexNet 位于多个基础应用之后，不能作为新手刚有一颗 ALU 时的首个主线挑战。
其条件体现足够的并行 ALU、缓存与内存，不要求 Tensor 单元：游戏允许普通浮点卷积。
大型合约提供新的投资目标，玩家仍能在挑战间经营普通订单、调整硬件策略。
应用顺序是教学与剧情编排，不是对真实软件发展历史的完整复刻。
AlexNet 与 Transformer 的名称、年份是历史灵感；客户、对白、工作量与奖励均为虚构。
2026 AI 工厂是架空终章；通关后保留工厂继续经营，也可以清空存档重玩。

## 为什么缓存与专用部件值得买

重复读取数据的订单从缓存获得较明显帮助；主要读取新数据的流式订单获益较小。
TMA 偏向改善异步搬运，Tensor 与 TMEM 偏向相应的矩阵与注意力任务。
玩家比较「订单做什么」和「工坊缺什么」，决定添 ALU、加缓存还是补数据供给。
收益使用游戏归一化单位，不映射真实命中率、带宽、延迟或 GPU 性能。
硬件发展区可介绍技术背景，但不能把虚构收益当作硬件评测或架构结论。

## 挂机、存档与重玩

- 页面打开时工坊自动经营，玩家随时购买升级、查看订单并选择大型合约。
- 进度自动保存在当前浏览器本地，不同浏览器或设备不自动同步。
- 返回时结算离线经营，最多计入 **8 小时**；离线收益不是后台执行真实计算。
- 清空存档会重置经营进度，操作前需明确确认；通关不强制重置。
- 首版不引入付费货币、账号或排行榜，游戏资金只在经营过程中获得。

## 实现边界与后续方向

界面位于 `web/game/`，规则与状态推进位于 `lib/idle-game.js`。
玩法在浏览器中运行，不提交真实 CUDA 任务，也不把收益绑定到实际 GPU。
未来可增加可选的「工程师视角」，连接仓库现有模拟器的可视化入口。
后续可扩展能耗预算、客户偏好与瓶颈提示；先确保两条发展线清晰、选择有效。
